# Maximus workflow integration (API v1)

The backend implements the flow below. `openapi.json` is exported from the running application definition and is the source of truth for request/response shapes. The existing frontend placeholders must be connected by the frontend owner; no frontend files were changed by Codex.

Base URL: `http://localhost:8000`. Health stays `GET /api/health` → `{"status":"ok"}`. New workflow paths use `/api/v1`; the old frontend placeholder paths are not aliases. All response field names are **snake_case**. Responses are the typed objects shown below, not the old `ApiResponse<T>` wrapper.

1. `POST /api/v1/onboarding` with `{"full_name":"Demo Learner","track":"career_first","target_role":"Python Backend Developer","skills":["Python"],"experience_level":"entry","weekly_hours":5}` → 201 `{learner, session_token, storage}`. For `skills_first`, omit target_role and supply at least one skill. Career-first requires target_role.
2. Preserve `learner.id` and the session token for the current browser session. All learner routes require `Authorization: Bearer <session_token>`. This is an opaque demo session credential, not full account authentication. Never place it in URLs or logs. Losing it means creating a new demo learner.
3. `POST /api/v1/learners/{learner_id}/assessments` → `{assessment, storage}`. Render each question's `id`, `prompt`, `options`, `skill`, and `difficulty`. Options have zero-based indices. Assessment IDs and question IDs are UUID strings. `target_role_source` distinguishes an explicit career choice from an AI suggestion. No answer keys or rationales are sent to the browser.
4. `POST /api/v1/learners/{learner_id}/assessments/{assessment_id}/submit` with `{"answers":{"<question-id>":0,"<question-id-2>":2,"<question-id-3>":1}}` → `{result, storage}`. Supply exactly one integer index per question. Show `score` (0–100), `skill_scores`, and `evidence_note`. Quiz observation does not establish independently verified professional skill. Submission is final for this assessment; repeat submissions return 409. Request a new assessment to retake.
5. `POST /api/v1/learners/{learner_id}/roadmap` → `{roadmap, storage}`. Render `summary` and ordered `steps`. Each step has an original `practice_task`, `objective`, `estimated_hours`, `prerequisites`, and status. These are AI-generated learning suggestions; no courses or job listings are invented. Weaker assessed skills are prioritized.
6. `PATCH /api/v1/learners/{learner_id}/roadmap/steps/{step_id}` with `{"completed":true}` → updated `{roadmap, storage}`. Only an available step can be completed; its successor unlocks. Completion is learner-reported, not independently verified. Repeating completion of the same step is safe. A new assessment resets the current result and roadmap.

Read routes: `GET /api/v1/learners/{id}`, `/assessment`, `/result`, `/roadmap`, and `/events`. Append suffixes to `/api/v1/learners/{id}`. Events contain actual node start/completion/failure timestamps and operation IDs for Skill Detective, Career Architect, Assessment Architect, Learning Curator, and Adaptive Mentor. Empty activity is a valid empty list. The most recent 200 events are retained.

`GET /api/v1/status` exposes `{mode, durable, reason}`. Every workflow response includes this `storage` object. If mode is `memory`, show a visible “Temporary demo session — data is lost when the server restarts” notice. Use one backend worker and no automatic reload during a demo. All users in one server process share one repository, with learner resources isolated by session token. Ten assessments per learner are allowed in this MVP.

AI requests may take up to 45 seconds per provider per model call; assessment generation performs two calls and roadmap generation performs one. Increase the frontend's 15-second timeout to at least 120 seconds for NVIDIA-only generation (up to 300 seconds if all three fallback providers are configured). Display pending/error states; do not invent results on timeout. Avoid repeated concurrent generation. After a browser timeout, check the read route before retrying: an operation may still have completed server-side.

Errors use `{"detail":...}`: 401 missing session, 404 missing resource/invalid session, 409 prerequisite or concurrent state conflict, 422 invalid input, 429 assessment limit, 503 unavailable AI/storage. FastAPI validation details may be an array. AI/storage SDK messages and secrets are never sent to clients. Generate POST requests are idempotent while an unsubmitted assessment/current roadmap exists; requesting an assessment after submission explicitly starts a new baseline.

CORS permits configured origins and GET/POST/PATCH with Authorization and Content-Type headers. Configure `FRONTEND_ORIGIN` as a comma-separated origin list if needed. Credentials remain backend-only.

Optional job search, curated resources, YouTube and public GitHub routes are now available independently of the learning workflow. Bot A integration details and provider-term display requirements are in [BOT_A_INTEGRATIONS.md](BOT_A_INTEGRATIONS.md). Consult the regenerated OpenAPI schema for exact shapes.
